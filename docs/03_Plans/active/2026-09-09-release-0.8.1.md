# Release 0.8.1

Date: 2026-09-09
Summary: harden error translation and track forward-sdk 0.1.5

## Changes

- Widen the client's error translation so anything the SDK raises reaches callers as
  `ForwardClientError`, not only subclasses of the SDK's own base error. Four callers treat that
  type as a signal to degrade: three fall back to inline NQE source when a bundled query is
  unpublished, and the planner disables destructive reconciliation when snapshot metrics are
  unavailable. An untranslated failure bypassed all four.
- Fix the concrete case behind that. On `forward-sdk` 0.1.4 a response the SDK could not parse
  raised pydantic's `ValidationError`, which is not a `ForwardError`, so it escaped every recovery
  path. Confirmed by direct comparison: 0.1.4 leaks `ValidationError`, 0.1.5 raises
  `ForwardResponseError`.
- Keep `ForwardConfigurationError` distinct rather than flattening it into `ForwardClientError`,
  since callers distinguish the two.
- Track `forward-sdk` 0.1.5, which also carries `to_api()` on repository and draft rows, an opt-in
  snapshot cache TTL that is off by default, and corrected rate-limit documentation.

The wider catch is deliberate belt and braces. 0.1.5 closes the known gap at source, but catching
only the SDK's base class would let the next such gap through on a version bump.
