# Release 0.6.0 — Contract, Scope, and Query Lifecycle Hardening

Date: 2026-08-06
Status: complete

## Goal

Ship a compatibility-tested maintenance release that corrects the Forward-to-Nautobot
device model contract, adds explicit device-population filters, and makes bundled NQE
publishing and source verification part of the plugin's supported operational workflow.

## Scope

- Map Forward manufacturer to Nautobot Manufacturer, hardware model to DeviceType,
  and operating-system family to Platform.
- Add persisted allowlists for manufacturer, functional device class, and hardware model.
- Keep saved NQEs unparameterized and primary-keyed for diff eligibility; build an exact
  current-device membership set and apply it to full-query and diff rows in the planner.
- Preserve raw direct-device and `scope_devices` attribution fields in query results. Fail
  closed for filtered prefix slices where safe contributor attribution cannot be returned at
  route-table scale.
- Treat filtered runs as create/update-only until per-profile managed-object ownership is
  available; never delete or deactivate objects merely because they are outside a filter.
- Persist a deterministic scope fingerprint so changing filters invalidates the
  same-snapshot skip baseline.
- Publish bundled NQEs idempotently to the organization repository, commit changed paths,
  and prove the committed source matches the packaged source.
- Fall back to packaged inline source through async execution when a bundled path is not
  published; report that the slice is full-query-only until it has a query ID.
- Keep full-snapshot execution on async query IDs and changed-snapshot execution on strict
  NQE diffs without a silent full-query fallback.
- Update package constraints, documentation, contract/wheel checks, and local real-Nautobot validation.

## Verification

- Focused query, registry, planner, client, write-path, job, form, and migration tests.
- Query contract and source-integrity gates.
- Build fresh wheel and verify every bundled NQE against that wheel.
- Real PostgreSQL/Redis/Nautobot runs against the supported Nautobot minor versions.
- Repeat-apply idempotence on the current supported Nautobot release.
- Authorized live publication, committed-source proof, async execution, and NQE-diff smoke.
- Sensitive-content scan over tracked files and history before publication.
- GitHub validation workflows removed by maintainer policy; the tag workflow is delivery-only.

## Release Safety

- Repository examples and fixtures remain generic and sanitized.
- No environment identifiers, credentials, network IDs, snapshot IDs, or returned customer
  rows are written to the repository or release artifacts.
- Plugin and query publication happen only after the complete release gate passes.
