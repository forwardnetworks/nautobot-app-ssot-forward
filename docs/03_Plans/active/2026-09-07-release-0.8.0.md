# Release 0.8.0

Date: 2026-09-07
Summary: move Forward transport onto the official forward-sdk

## Changes

- Replace the hand-rolled httpx client with `forward-sdk`, pinned exactly at `0.1.4`.
  The client drops from 1203 lines to roughly 470 and keeps only plugin vocabulary: connection and
  query-spec shapes, the response reshaping adapters expect, and the telemetry the SSoT job result
  persists.
- Hand retry, backoff, rate limiting, pagination guards, the async NQE poll loop, and the query
  library workflow to the SDK. No direct HTTP remains in the package; the single httpx reference is
  the transport type used for test injection.
- Parse bundled query contracts through `forward_sdk.nqe.files`, verified byte-identical to the
  previous parsers across all 16 bundled queries. Public names are unchanged so the release gates
  that import them keep working.
- Cache snapshot listing, resolution, and metrics in the client behind a lock. The SDK caches the
  query index but not these, and the planner resolves a snapshot once per slice across a thread
  pool.
- Keep single-page reads bounded, so `fetch_all=False` returns one page rather than every row.
- Read Forward's structured `reason` code when handling publishing errors instead of matching
  against the rendered text of an exception.
- Correct 17 test fixtures that wrapped NQE rows in a `fields` envelope Forward never sends.
  Stripping that envelope corrupts a row whose own column is named `fields`.
- Widen the `httpx` range to match the SDK, since the SDK now owns transport behaviour.
