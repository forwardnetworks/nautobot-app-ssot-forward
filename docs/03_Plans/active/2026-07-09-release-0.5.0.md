# Release 0.5.0

Date: 2026-07-09
Summary: REST API endpoints (health/status/support-bundle) + Prometheus metrics exporter

## Changes

Lessons ported from the sibling forward-netbox plugin (now at 2.4.4), which added
a REST API surface and a metrics exporter.

- **REST API endpoints** (`forward_nautobot/api/`, mounted at `/api/plugins/forward/`):
  - `GET health/` — compact liveness/health verdict (`healthy` / `degraded` /
    `unconfigured`) with plugin + Nautobot versions and readiness counts, for
    monitoring probes.
  - `GET status/` — the full per-profile operational status summary as JSON.
  - `GET support-bundle/` — the last persisted (redacted) support bundle plus its
    offline grade; `?profile=<name>` selects, `?grade=false` omits the grade.
  - All require authentication and never expose a stored credential.
- **Prometheus metrics exporter** — `nautobot-server forward_metrics` emits
  text-exposition metrics (profile counts, per-profile last-run timestamp/age/failed,
  and nautobot-ssot Sync total when present). Rendering logic is a pure, unit-tested
  module (`integrations/forward/metrics.py`); the command is a thin ORM wrapper.

- **PyPI publishing (Trusted Publishing)** — `.github/workflows/release.yml` now
  has a `publish-pypi` job that uploads the sdist + wheel to PyPI via OIDC (no
  stored token), gated on a real `v*` tag and a `pypi` GitHub environment. The
  build job also emits a non-blocking CycloneDX SBOM artifact. `scripts/release.py`
  docstring updated to reflect that the tag triggers the PyPI publish.
  - One-time setup (in the workflow header): add the GitHub Trusted Publisher on
    PyPI and create the repo `pypi` environment before the first tag publishes.

- **Local Nautobot container test stack** (`development/`) — Nautobot 3.1.6 +
  Postgres + Redis compose so the full suite (contrib / REST-API / crypto tests
  that skip without a real Nautobot) runs locally instead of on a remote box.
  `conftest.py` runs `nautobot.setup()` when `DJANGO_SETTINGS_MODULE` is set (no-op
  otherwise); `nautobot_config.py` keeps Nautobot's Redis cache when
  `NAUTOBOT_REDIS_HOST` is set. In-container: 158 passed / 0 failed, migration 0006
  applied, repeat-apply idempotence PASS on a real DB, and the three REST endpoints
  verified live over HTTP.
- **Grader hardening** — `grade_support_bundle` now coerces numeric fields
  defensively; a redacted bundle carrying `"[REDACTED]"` where a count was expected
  previously 500'd the `support-bundle/` API endpoint (caught by the container HTTP
  smoke).
- **Delete-governance override audit** (backlog P1) — contrib deletes are gated per
  model by a zero-rows gate and a max-delete-fraction gate, each bypassable with a
  recorded override (who / why / when). `delete_policy="delete"` opts in;
  `delete_override_reason` Job input forces past a block. Surfaced in the support
  bundle. Live-verified: a 75% delete was blocked; the override let it through.
- **`dcim.Cable` import** (backlog) — network topology imported as cables from
  Forward's inferred interface links (`forward_cables.nqe` + custom idempotent,
  LAG-safe, conflict-skipping CRUD). Gated by `contrib_include_cables` (default on).
- **Local Nautobot container test stack** now the standard way to run the full
  suite (contrib / REST-API / crypto / cable / delete-governance) against a real
  Nautobot 3.1.6; latest fresh run: 173 passed / 0 failed.
- **IPAM parity trio** (closing the last core-Nautobot coverage gaps vs
  forward-netbox):
  - IPs are bound to their interfaces (`IPAddressToInterface`) and a
    loopback-terminated IP conservatively sets `Device.primary_ip4/6`.
  - Prefixes + IPs are scoped to their VRF namespace, so the same prefix/host in
    two VRFs no longer collapses (was a data-integrity bug).
  - VLANs are associated with their Forward site via Nautobot's multi-location M2M.
- **VirtualChassis intentionally not imported** — matches forward-netbox, whose VC
  query is a deliberate no-op (vPC/MLAG/HA are control-plane relationships, not VC
  memberships). Documented rather than built.

Parity note: FHRP/HSRP, BGP/OSPF/peering, ACI, and device-lifecycle objects are
*not* imported — Nautobot core has no model for them (they require separate
Nautobot plugins with different schemas), unlike NetBox where forward-netbox maps
them natively.

Note: credential encryption at rest (a forward-netbox lesson) was already present
here (`_encrypt_password`/`_decrypt_password`, Fernet keyed on `SECRET_KEY`).
